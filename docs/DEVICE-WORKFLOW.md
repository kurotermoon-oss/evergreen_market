# Работа с разных устройств

Источник актуального кода — [kurotermoon-oss/evergreen_market, main](https://github.com/kurotermoon-oss/evergreen_market/tree/main). Каждое устройство работает со своим Git-клоном. Папка, скачанная кнопкой Download ZIP, не умеет получать и отправлять изменения.

На новом устройстве один раз:

```sh
git clone https://github.com/kurotermoon-oss/evergreen_market.git
cd evergreen_market
npm ci
```

Откройте эту папку как проект. Не задавайте общий путь с другого компьютера. Если Git for Windows сообщает `schannel: SEC_E_NO_CREDENTIALS`, используйте `git -c http.sslBackend=openssl clone ...`; проверка TLS остаётся включённой.

Перед работой: `npm run sync`. Команда получает main с GitHub и обновляет только чистую копию без неопубликованных коммитов. При локальных изменениях она останавливается и показывает их, не сбрасывая файлы. `npm run sync:check` только сверяет состояние; код выхода 1 означает различия или ошибку подключения. Команды требуют Node и Git, но не установки npm-зависимостей.

При переходе на другое устройство сначала закончите публикацию текущей работы: проверьте изменения, добавьте только файлы задачи, сделайте коммит и отправьте его в main. На следующем устройстве снова выполните `npm run sync`. Для одновременной работы над разными задачами используйте отдельные ветки и объединяйте их через pull request; не редактируйте независимо один и тот же main с непереданными изменениями.

Агент начинает задачу со сверки GitHub по [AGENTS.md](../AGENTS.md). Для обычной передачи контекста достаточно: «Продолжи Evergreen, сверься с GitHub и WORK-STATE». Исправления публикуются в рамках порученного обновления после проверок. Если нужна только локальная проба, укажите это в запросе.

Сохранение на GitHub не равно запуску на сайте. После отправки кода нужно проверить успешный Railway deployment и публичный домен. При недоступном Railway подтвердить загруженные JS/CSS по новой сборке и проверить изменённые сценарии. Если deployment не подтверждён, сообщить об этом отдельно.

GitHub хранит код. Заказы, остатки и клиенты находятся в production PostgreSQL, изображения — в настроенном хранилище. Их не переносят между устройствами через Git; `.env`, ключи, дампы и `.preview/` не публикуют. Для безопасной проверки интерфейса используйте `npm run preview:refresh` и `npm run preview:design`; это не отправляет заказы.

Подключённый GitHub-коннектор может публиковать изменения, даже если локальный Git не авторизован для push. После такой публикации агент получает новый main и проверяет совпадение файлов. Токены не сохраняются в репозитории. На устройстве без коннектора отправка требует обычного входа в GitHub через Git Credential Manager или GitHub CLI.
