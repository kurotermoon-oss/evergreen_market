# Telegram: управление заказами

Mini App команды: `/telegram/admin`. По умолчанию использует существующего бота из `TELEGRAM_BOT_TOKEN`; отдельный бот необязателен. Серверный API `/api/telegram/admin` и сессия дают только права на работу с заказами. Будущий клиентский Mini App может использовать того же бота, но должен иметь отдельные маршруты и права.

## Подключение на Railway

1. Оставьте существующие `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` и `TELEGRAM_CHAT_ID`. Дублировать токен не требуется. Имена переменных чувствительны к регистру: используйте именно `TELEGRAM_BOT_TOKEN`.
2. Добавьте две переменные в серверный сервис Railway, без префикса `VITE_`:
   - `TELEGRAM_ADMIN_USER_IDS`: числовые Telegram user ID сотрудников через запятую. Не username, не ID группы. Проверяйте принадлежность каждого ID сотруднику. `TELEGRAM_CHAT_ID` не используется как источник административных прав.
   - `TELEGRAM_ADMIN_APP_URL`: `https://evergreenmarket.com.ua/telegram/admin`.
3. Каждый сотрудник открывает личный чат с существующим ботом и нажимает Start. Настройте кнопку «Замовлення» с URL из предыдущего пункта. Для общего бота предпочтительна персональная кнопка через [setChatMenuButton](https://core.telegram.org/bots/api#setchatmenubutton): укажите `chat_id` сотрудника и `menu_button` вида `{"type":"web_app","text":"Замовлення","web_app":{"url":"https://evergreenmarket.com.ua/telegram/admin"}}`. Выполните настройку для каждого разрешённого ID. Это оставляет общее меню доступным для будущего клиентского приложения.
4. Альтернатива — общая Menu Button через [BotFather](https://t.me/BotFather), `/setmenubutton`. Она видна всем пользователям бота, но сервер разрешает вход только ID из списка. Не заменяйте уже используемое клиентское меню без необходимости.
5. Перезапустите сервер после изменения переменных. Откройте приложение кнопкой меню: разрешённый аккаунт видит заказы, посторонний получает отказ. Удаление ID из списка и перезапуск отзывают даже уже выданную сессию.

Если нужен отдельный административный бот, создайте его в BotFather и дополнительно задайте `TELEGRAM_ADMIN_BOT_TOKEN`. Непустое значение имеет приоритет над `TELEGRAM_BOT_TOKEN` и используется одновременно для проверки входа и административных уведомлений. В этом случае настраивайте кнопку и нажимайте Start у отдельного бота. Удаление или пустое значение этой переменной возвращает использование общего бота; остальные Telegram-функции сайта продолжают использовать `TELEGRAM_BOT_TOKEN`.

Mini App не запускает дополнительный `getUpdates` или webhook и не потребляет обновления существующего бота. Для подключения не изменяйте его текущий механизм обработки сообщений. Числовой ID сотрудника можно взять из Telegram data export; не запускайте второй опрос действующего бота для получения ID.

Токен не помещать в Git, URL, клиентский код или чат. Без разрешённых ID вход остаётся закрыт даже при наличии общего токена. Для уведомлений нужен корректный HTTPS URL приложения. Миграция БД для этой функции не нужна.

## Поведение

- Активные заказы и история, поиск по номеру/имени/контакту, фильтры статусов, страницы по 50 записей. Обновление раз в минуту, при возвращении в Telegram и вручную; на время подтверждения действия автообновление приостановлено.
- Карточка: контакты, комментарий, исторические цены/количества, текущее наличие и поставщик, безопасные ссылки, история действий. Скрытые/удалённые товары не теряют исторические строки заказа.
- Подтверждение → подготовка → готовность → выдача; отмена с причиной. В истории сохраняется Telegram ID сотрудника. При готовности используется существующий механизм уведомления покупателя.
- Новый заказ сохраняется до отправки уведомлений. Настроенный бот отправляет краткое сообщение каждому разрешённому ID и кнопку именно этого заказа. Прежнее уведомление в `TELEGRAM_CHAT_ID` сохраняется; если это личный чат того же сотрудника, в нём будут оба сообщения. Сетевой отказ не блокирует оформление. Отправка best effort, без очереди повторов: при сбое ориентируйтесь на список заказов в панели.
- Сессия живёт 30 минут, только в памяти вкладки. После истечения нужно закрыть и открыть Mini App. Сервер проверяет Telegram-подпись и возраст initData до 5 минут, затем проверяет разрешённый ID на каждом запросе. Сессия Telegram не подходит к `/api/admin` и клиентским маршрутам.
- Проверка ожидаемого статуса предотвращает повторные и устаревшие действия. PostgreSQL блокирует строку заказа в транзакции для всех административных каналов до изменения остатков/счётчиков. Уведомление о готовности отправляется после сохранения.
- Веб-админка остаётся отдельным входом. Mini App не предоставляет редактирование каталога, массовые операции или закупку у поставщика.

## Проверки

`npm run test:telegram-admin`, `npm run test:storefront`, `npm run build`.

Безопасная демоверсия: `npm run preview:design`, затем `/preview/telegram-admin`. Данные вымышлены, изменения только в памяти вкладки, API записи блокируется preview-сервером. Демо не включается в production-сборку.

Перед использованием командой проверить на реальных Telegram iOS/Android: вход разрешённого/постороннего аккаунта, кнопку меню, клавиатуру, возврат, уведомление с открытием конкретного заказа, истечение сессии и отзыв доступа. Browser preview не заменяет эту проверку. Не создавать реальные покупательские заказы только для проверки дизайна.

Список первоначально читается через существующий репозиторий заказов и фильтруется на сервере. При росте истории стоит перенести фильтры/пагинацию в SQL. Гарантии одновременной работы нескольких серверов относятся к PostgreSQL; локальный JSON — только для одного процесса.

Официальная документация: [Mini Apps и проверка initData](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app), [кнопки бота](https://core.telegram.org/bots/api#inlinekeyboardbutton).
