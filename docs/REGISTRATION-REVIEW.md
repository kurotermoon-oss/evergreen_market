# Регистрация: проверка и предложение

Проверено 10.09.2026 по клиенту, серверным обработчикам и валидаторам. Новые реальные аккаунты и заказы не создавались. Это предложение следующей доработки, не описание уже внедрённого входа через Telegram.

## Что работает сейчас

- Заказ без аккаунта поддерживается: достаточно имени и телефона либо Telegram. Минимум поставщика проверяется отдельно от регистрации.
- Регистрация просит имя, один контакт, пароль от восьми символов и его повтор. Форма также показывает четыре необязательных поля адреса — при действующем самовывозе это лишняя нагрузка.
- После регистрации сервер сразу устанавливает сессионную cookie на 30 дней; отдельный повторный вход не требуется.
- Контакт при регистрации проверяется по формату, а не по владению. Существующее подтверждение Telegram — отдельный сценарий уже созданного аккаунта, не вход без пароля.
- В изученных маршрутах/форме нет самостоятельного восстановления пароля. Регистрационный маршрут, в отличие от входа, не подключает отдельный ограничитель частоты.
- Первое поле нового пароля сейчас имеет autocomplete=current-password; это мешает правильному предложению нового пароля менеджером паролей.
- Клиент считает регистрацию/вход неуспешными, если следующий запрос истории заказов завершился ошибкой, хотя сессия уже создана. Эти операции стоит разделить.

## Рекомендуемый пользовательский путь

1. Основной сценарий: «Оформити без реєстрації» → имя и один контакт → подтверждение заказа. Адрес не спрашивать, пока доступен только самовывоз.
2. После покупки предложить «Зберігати замовлення та дані» как необязательное действие. Не превращать указанный контакт в аккаунт автоматически и не привязывать чужую историю по одному введённому номеру.
3. Для постоянных покупателей — «Увійти через Telegram»: единый вход и создание аккаунта после подтверждения Telegram. Существующий вход по паролю сохранить для действующих клиентов и людей без Telegram.
4. В короткой резервной регистрации оставить имя, один контакт и пароль с кнопкой показа; убрать повтор пароля и поля адреса. Подтверждение владения контактом требуется перед присоединением существующего аккаунта/заказов.

## Объём следующей реализации

- Сначала сократить форму, исправить autocomplete и обработку ошибки загрузки истории, добавить ограничение частоты регистрации. Проверки: гость, действующий аккаунт, неправильный контакт, дубликат, медленный/недоступный запрос истории.
- Затем подключить официальный Telegram Login / OIDC в существующем Express-приложении. Потребуются разрешённые адреса и учётные данные приложения в BotFather; новый хостинг и SMS-сервис не нужны.
- Проверять подпись токена, issuer, audience, срок и одноразовую привязку попытки входа на сервере. Использовать стабильный Telegram ID, не изменяемый username. Запрашивать телефон/право сообщений только при необходимости и согласии клиента. Существующий аккаунт связывать через подтверждённую сессию.
- Критерии: отмена входа не теряет корзину; повторное подтверждение не создаёт дубль; вход возвращает к оформлению; пользователь без Telegram может купить как гость; секреты только в Railway variables.

Официальная актуальная документация: [Telegram Login](https://core.telegram.org/bots/telegram-login). Telegram предлагает бесплатный вход с подтверждением; точное число нажатий зависит от устройства и текущей сессии Telegram.
