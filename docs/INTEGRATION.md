# Размещение на evergreenmarket.com.ua

Лендинг подготовлен как отдельная статическая страница существующего сайта. Новый домен, база данных, Node-сервер и платные зависимости ему не нужны. Дополнительная плата за отдельный хостинг не требуется, если текущая площадка позволяет добавлять статические файлы в существующий проект; её тариф и доступы здесь не проверялись.

## Готовый вариант: /evergreen/

1. Выполнить `node scripts/build.mjs` в этой папке. Готовые файлы находятся в `dist/evergreen/`; архив `evergreen-landing.zip` содержит эту папку.
2. Если исходный проект собирается Vite, скопировать папку `dist/evergreen/` из этого проекта в `public/evergreen/` исходного проекта сайта. Добавить её до сборки, чтобы следующий релиз не стёр страницу. Для другой системы использовать её каталог публичных статических файлов.
3. Собрать и опубликовать существующий проект обычным способом. Результат должен открываться по `https://evergreenmarket.com.ua/evergreen/`.
4. Если сервер перенаправляет все запросы в React-приложение, дать реальным статическим файлам приоритет перед SPA fallback. Проверить URL с завершающим слешем: относительные пути ресурсов рассчитываются от папки страницы. Для `/evergreen` настроить перенаправление на `/evergreen/`.
5. Добавить в существующую навигацию обычную ссылку `<a href="/evergreen/">Вигідні покупки</a>`. Для собственного SPA-переключателя использовать полную навигацию браузера, чтобы он не перехватил новый путь как неизвестный экран.

Не заменять действующий корневой `index.html`: иначе можно нарушить каталог, корзину, аккаунты и административную часть. Все кнопки лендинга уже ведут в действующий `/catalog`, оформление заказа остаётся там.

## Если лендинг должен стать главной

Нужны исходники основного приложения. По публичной сборке обнаружены React и внутренний переключатель экранов: `/`, `/catalog`, `/how-it-works`, `/contacts`, `/cart` и другие. Это не подтверждает конкретный хостинг или структуру репозитория.

Вариант интеграции: перенести содержимое `main` в компонент главной, подключить стили и сохранить общие шапку, подвал, корзину и маршруты сайта. Класс `evergreen-landing` поставить на обёртку страницы; при переносе атрибуты HTML преобразовать в JSX. Логику `script.js` подключить через эффект с очисткой слушателей/наблюдателя. Не загружать этот файл повторно при каждом переходе. Префикс `eg-` уже встречается в действующем сайте: перед интеграцией компонента переименовать селекторы лендинга в `eglp-` либо изолировать их CSS-модулем. Для самостоятельной страницы конфликтов нет.

## Проверка после публикации

- `/evergreen/` отдаёт лендинг, CSS и оба изображения загружаются.
- Кнопки открывают каталог; существующая корзина продолжает работать.
- Ссылки Telegram, Instagram и карты ведут к нужным контактам.
- На телефоне нет горизонтального прокручивания и перекрытия контента нижней кнопкой.
- Клавиатура, раскрытие вопросов и отключение анимаций работают.
- Согласовать адрес, часы, ассортимент и условия самовывоза перед публичным запуском. Здесь они взяты из публичной сборки сайта 07.09.2026.

## Что уже проверено локально

Синтаксис JavaScript, наличие локальных ресурсов, уникальность HTML ID, цели внутренних ссылок и сборка пакета. Автоматизированная визуальная проверка браузером не выполнялась. Предпросмотр: `node scripts/serve.mjs`, затем http://127.0.0.1:4173/ . Файл `landing/index.html` также открывается напрямую.

Файлы не опубликованы на действующем домене: в рабочей папке нет исходников магазина и доступа к его размещению. Для завершения интеграции нужен репозиторий сайта либо его исходная папка и существующий способ публикации. Пароли в чат не нужны.
