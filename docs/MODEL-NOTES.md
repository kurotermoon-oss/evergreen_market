# Astra 6: расход и порядок работы

Проверено 09.09.2026. Читать при вопросах о модели; для обычных правок сайта эта справка не нужна.

## Что подтверждает документация

[Статья об Astra](https://openai.com/index/gpt-6-astra/) показывает улучшения на конкретных задачах и тестах; из этих результатов нельзя вывести процент экономии для Evergreen. [Руководство модели](https://developers.openai.com/api/docs/guides/latest-model) советует проверять инструкции в MD/skills, явно задавать стиль ответа и ограничивать проверки масштабом изменения.

[Правила расхода Codex](https://learn.chatgpt.com/docs/pricing) связывают использование лимита с моделью, объёмом контекста, reasoning, инструментами и кешированием. Короткий запрос или ответ сам по себе не означает дешёвую задачу. Пятичасовое окно подписки нельзя пересчитать по тарифам API. Точной разбивки прошлой работы Evergreen по токенам здесь нет.

## Рекомендация для этого проекта

Это стартовая рабочая эвристика, а не измеренная гарантия качества или экономии.

| Effort | Когда выбирать |
| --- | --- |
| low | Текст, одна кнопка, известная CSS-ошибка, документация, отправка готового коммита |
| medium | Обычный режим: экран, адаптивность, реализация согласованного дизайна/функции |
| high | Новая общая дизайн-система, неоднозначный сценарий, сложный баг или несколько связанных подсистем |
| xhigh и выше | Только когда сложность конкретного этапа оправдывает дополнительные затраты |

Для следующих задач начните с **medium**. Качество дизайна оценивайте по иерархии, композиции, типографике и удобству на реальных экранах. Высокий effort не заменяет ясную цель или визуальную проверку. При неудовлетворительном результате сначала уточните причину; повышение effort полезно не во всех случаях.

Выбор модели и effort меняется в интерфейсе Codex. Эти MD-файлы настройки не переключают; текущий уровень не менялся. Разбиение на этапы тоже не понижает его автоматически. Astra сохраняется выбранной моделью, пока владелец не попросит другую.

## Порядок выполнения

1. Из запроса сформулировать результат и проверяемые критерии. Для большого запроса — несколько последовательных этапов, каждый даёт законченный сценарий.
2. Найти нужную строку карты проекта, прочитать её файлы. Бизнес-справки и историю подключать по необходимости.
3. Выбрать одно направление, реализовать этап, проверить затронутые сценарии. Расширять проверку при изменении общих компонентов или выявленной проблеме.
4. Продолжать до полного запрошенного результата без согласования каждого обычного шага. Обновить короткое состояние после существенного этапа; не создавать отчёт на каждую мелочь.

Пример общей задачи: общие элементы → каталог/товар → корзина/кабинет → админка → итоговая проверка и публикация. Это последовательность внутри задания, а не пять обязательных новых разговоров.

Достаточный запрос владельца:

> Сделай [экран/сценарий] удобнее для [покупателя/администратора]. Сейчас мешает [проблема]. Результат: [2–3 критерия]. Остальное реши самостоятельно.

Можно продолжать давать комплексные задания — разбивать их обязан агент. Для оценки результата сравнивайте несколько похожих задач: выбранный effort, расход в Usage, время, готовый результат и число переделок. Параллельные задачи аккаунта и сброс окна искажают такое сравнение. Без замеров не обещать экономию в процентах.

## Если позже понадобится API

[Карта модели](https://developers.openai.com/api/docs/models/gpt-6-astra): `gpt-6-astra`, уровни `low/medium/high/xhigh/max`, без `none`. Для инструментов использовать Responses API. Руководство описывает `configuration_update` для смены effort с сохранением префикса кеша; совместимость нужно проверить перед внедрением. Это возможности API, не настройки данного сайта или Codex через Markdown. OpenAI API сайту сейчас не нужен.

[Как загружается AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md): инструкция зависит от корня проекта и рабочей директории. Открывать основной проект Evergreen, а не папку старого HTML-прототипа. Карту и состояние читать по задаче, не загружать все MD постоянно.
