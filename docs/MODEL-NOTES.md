# Расход Codex: рабочие правила Evergreen

Обновлено 12.09.2026. Справка для вопросов о расходе; не читать при обычных правках сайта.

## Что обнаружено в этой задаче

- Повторные большие чтения одних функций и документации расширяли контекст.
- Проверки интерфейса многократно повторялись после небольших изменений; не всегда было ясно, какое сомнение они должны снять.
- Скриншоты иногда выводились дважды: инструмент уже показывал изображение, затем оно повторно передавалось в emitImage.
- Проверка размеров сначала попала не в ту вкладку. Несовпадение значений полей в снимке DOM и на экране вызвало лишние попытки ввода и перезапуск инструмента.
- Контрольная точка и отчёт о дизайне повторяли друг друга; появлялись дополнительные коммиты только для статуса публикации.

Это наблюдения за работой, а не точная разбивка расхода по токенам. Главная мера — исполнение короткого цикла в AGENTS.md: найти → изменить → проверить затронутое → опубликовать → остановиться. Дополнительный вызов нужен, когда он устраняет конкретную неопределённость.

## Настройки и измерение

Практический старт: low для текста/локальной CSS-правки, medium для экрана или обычной функции, high для сложного диагноза. Это эвристика, не гарантия экономии. Модель и effort этим изменением не переключались. Системные инструкции, инструменты и тарификацию AGENTS.md не меняет.

[Документация Codex](https://learn.chatgpt.com/docs/pricing#what-can-i-do-to-make-my-usage-limits-last-longer) рекомендует ограничивать контекст, исходные материалы и размер AGENTS.md, отключать ненужные MCP и выбирать меньшую модель для рутинных задач. Расход лимита зависит также от reasoning, инструментов и кеширования; длина ответа не равна стоимости задачи. Не пересчитывать подписку по API-тарифам.

[Руководство модели](https://developers.openai.com/api/docs/guides/latest-model#testing-and-verification) рекомендует повторять успешные проверки только после значимых изменений, ошибок или оставшихся сомнений.

Сравнивать несколько сходных законченных задач: модель/effort, изменение Usage, время и переделки. Отмечать параллельные задачи и сброс окна. Не обещать процент экономии без таких замеров. После завершения большого независимого этапа можно начать новую задачу в том же проекте; актуальное состояние остаётся в GitHub и коротком checkpoint.
